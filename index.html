Three Metrics, Three Questions

TTFT

Time from request sent → first streamed token. The "staring at nothing" wait. Queue + prefill + first byte travel.

Decode tok/s

(tokens−1) ÷ seconds after first token. Raw generation speed once tokens flow. Model capability, minus the wait.

Overall tok/s

tokens ÷ total seconds. End-to-end speed including the prefill wait. What the call actually felt like.

Install

Global (all pi sessions)

Installs into ~/.pi/agent/extensions/ — auto-discovered in every session.

Project-local

Copies into .pi/extensions/ — loads when the project is trusted.

# One-liner global install pi install git:github.com/itlmkz/pi-LLM-speed-test-extension # Or clone and copy manually cp speed-counter.ts ~/.pi/agent/extensions/ # then /reload in a running session

Commands: /speed (session table), /speed clear, /speed off, /speed on

Why From Your Seat?

Published leaderboards measure from datacenters in a few regions, with synthetic prompts. The weekly decision — which provider and model should I route my coding work through — depends on where you are, what your machine does, and which keys you already hold.

Your network path

Geography is the biggest latency term — hundreds of ms before any model runs. We measure your path.

Your keys, your config

Reads providers straight from pi's settings. No extra setup. Strict-CORS providers (Anthropic, OpenAI direct) work because it runs in Node, not the browser.

Your history

/speed builds a session log with per-model medians, totals, and cost. No dashboard to visit — it's in your terminal.
